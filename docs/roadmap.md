# Drake autodev 路线

一个阶段对应一个可恢复的 GitHub Issue；总看板统一管理六仓，仓库保留本引擎的原生设计。先查同题 Issue/PR 和实际合入状态，再继续工作。

| 阶段 | 交付切片 | 依赖 | 状态 |
|---|---|---|---|
| E0 | 双路线导航与固定版本源码导读 | 无 | 首批导读已交付 |
| E1 | 建模、坐标、状态与时间专题 | E0 | [专题已交付](modeling-state-time.md)，[源码/静态验证](evidence/e1-validation.md)；未运行 |
| E2 | 驱动、机器人与任务接口专题 | E1 | 待开发 |
| E3 | 接触、求解器与力观测源码专题 | E1 | 待开发 |
| E4 | 传感器、渲染与可视化专题 | E1 | 待开发 |
| E5 | 批量、学习接口与数据专题 | E2、E4 | 待开发 |
| E6 | 引擎特色、扩展与能力边界专题 | E3 | 待开发 |
| E7 | 双路线课程审校与 DexLab 复用入口 | E2–E6 | 待开发 |

E0 交付的是导读与导航，不是所有专题。E1–E6 逐个展开目录中的知识点，E7 按完整课程契约审校。依赖必须以实际文档或合入提交核实，不能仅凭 Issue 关闭。

每个 Issue 记录目标、范围、先修、固定版本/来源、交付文件、易错点、验收命令和剩余问题。本轮验收为文档链接、源码/公式核对及最小片段的语法检查；明确区分未运行、源码核对和运行验收。无新实验、训练、性能基准、跨引擎框架或评分器。

有可执行任务时按依赖推进；阻塞时记录原因和恢复条件。没有用户要求不创建定时任务。研究数据与实验最终引用 DexLab。

## E1 完成后的下一项判断

E1 展开了 A1/A2 与 B0/B4 的建模/状态/时间基础；动态接触、完整动力学装配、稳定性和可微限制留给 E3。依赖图中 E2、E3、E4 将在 E1 合入默认分支后可执行。建议下一项 E2：已有模型/状态与事件语义可直接支撑驱动、机器人和任务接口，之后 E3 深入接触数值。该建议不是已领取或已完成；执行前重读远端 Issue/PR 与 base，避免重复任务。
